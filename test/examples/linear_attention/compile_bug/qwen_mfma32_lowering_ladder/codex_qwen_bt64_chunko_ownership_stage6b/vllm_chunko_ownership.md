# vLLM Triton BT64 Chunk-O Ownership

Authoritative installed source:
`/opt/venv/lib/python3.12/site-packages/vllm/model_executor/layers/fla/ops/chunk_o.py`.
The kernel has grid `(ceil(V/BV), NT, B*H)` and creates `b_o:[BT,BV]` plus
`b_A:[BT,BT]` in one CTA. It computes QH and QK in its K loop, applies causal
masking to `b_A`, then computes `b_A @ V-new` and writes the final output.
There is no partial-output global materialization or atomic.

A fresh warm T=2048 query of the actual Triton autotuner selected:

```text
BK=32, BV=64, num_warps=4, num_stages=2, num_ctas=1
```

Thus the actual specialization has grid `(2,32,8)`, 256 threads/CTA, and 512
CTAs: two CTAs per chunk/head, each owning `[token64,V64]`. The exact
lane-to-fragment permutation is generated by Triton block-dot lowering and is
not represented in the Python source. This audit deliberately records it as
not source-observable rather than inventing a lane mapping.

The Stage 6A full-graph rocprof resource row for this same `BV=64`, four-wave
geometry is: `MFMA=81920`, `VMEM=71680`, `LDS=245760`, `VGPR=100`,
`Accum_VGPR=36`, `SGPR=96`, `Scratch=0 B`.
